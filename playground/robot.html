Bug 3 of 3 · inspired by HATRIC, the trivia robot I’m building

“Everyone deserves a turn.”

A trivia robot is hosting three players. Its turn-taking rule always picks whoever sits in Seat 1, so one person answers every question while the others wait. It even asks Seat 1 when nobody is sitting there.

1. Who’s at the table? (fictional players)

    2. Choose the selection rule

    What’s going on here?

    This is a selection rule: given the current state (who’s present and how many turns each has had), pick the next person to address. The flawed rule is a constant: it returns Seat 1 no matter what. The fixed rule filters to eligible players, sorts by fewest turns, breaks ties by longest wait and then seat number, and takes the first result. Because the tie-break is deterministic, the same state always produces the same choice, which makes the behavior easy to explain and test.

    Honest label: this is a scripted simulation. It is not a live language model and not a reproduction of HATRIC, where these decisions come from an LLM agent working with vision input. It just shows why “who hasn’t spoken yet?” is worth encoding explicitly.
