What’s going on here?

This is about where state lives. In temporary mode the entries exist only in a JavaScript variable, so “reopening” starts with fresh, empty memory. In persistent mode, every change is serialized to JSON and written to localStorage, and reopening reads it back and validates it before showing it. Because it’s real storage, your hike is still here even if you reload the page.

This browser demo uses localStorage. The actual TrackTheTrek project is a Java desktop app that persists hikes to a JSON file: the same idea in a different environment. “Reset this demo” deletes only this demo’s storage keys. If your browser blocks storage, the persistent option is turned off and everything else still works.

Honest label: a simplified demonstration inspired by TrackTheTrek, not a reconstruction of a real bug in that project.
